## 仍未通过

专用夹具的玻璃、水、熔炉和石砖，实际渲染帧中处于可见状态且进入正确队列，但 PNG 中仍不能确认完整模型显示。追加诊断中四目标均有正确位置、非空顶点及不透明顶点 alpha，MMCE／Terminal 的隐藏器均未激活。因此不能把问题归咎于“选区为空”或未经验证的其他模组隐藏逻辑；GPU 提交与渲染状态仍需继续定位。

最后一轮仅在本测试屏幕临时包裹原上传器，原样委托绘制并在完成后恢复。记录到实际生产路径的 53 次上传，四目标顶点数仍为 24／32／16／16，RGB 和 alpha 有效，UV／光照坐标存在，上传前后未报告 GL 错误。关闭面剔除在实际上传前也得到确认，但独立诊断 PNG 仍有相同异常。这缩小了调查范围，不能证明全部 GPU 状态、纹理及最后呈现正确。诊断图不计为产品默认渲染通过；记录中的 glGetError 会消费错误，此副作用仅属于明确标注的诊断帧。

另只读检查实际启用资源包与原始 PNG：熔炉、石砖、玻璃最终来自 Modernity，水来自 OceanWater；原始颜色及 alpha 未见足以解释模型完全缺失的异常。自定义覆盖资源目录在本副本中不存在。原图与统计保存在 `validation\native-qa\texture-audit-20261024-6cfca60b\texture-audit.json`，SHA256 `CA9019E093CC0AE3C83D05B2B90E8F2ACA3A43C2F2137466A79E16808768FD83`。该检查只覆盖原图及包优先级，不证明 GPU atlas、CTM 或其他运行时纹理处理正确。
