# Ponder 单人内容创作候选使用说明

本说明对应 `0.3.0-beta` 单人融合候选，不代表已经完成最终发布验收，也不表示候选已经安装到原实例。目标是当前 Minecraft 1.12.2 / Cleanroom 环境；没有扩展普通 Forge、Java 8 运行环境、多人内容同步或在线 AI。实际部署以独立安装收据为准，旧 Alpha 的运行结果不转记为本候选通过。

## 文档和预览

进入单人世界后使用 `/pondereditor`，或在思索目录下选择 `E`。宽屏显示列表、预览和属性三个区域；320×240 逻辑界面通过列表、预览、属性页切换。

`/pondereditor` 在聊天回车处理结束后的客户端刻打开编辑器，关闭后返回游戏而不是旧聊天框。它仍仅限单人世界；世界切换或期间出现其他界面时，旧打开请求会失效。若作者工作区无法读取或建立，会显示明确错误并写入游戏日志，不在每刻反复尝试。

顶部工具提供新建、文档、保存、撤销、重做、发布、独立预览、剪贴板 JSON 导入、JSON 导出、历史、素材交换和返回。三维选点与原版菜单捕获位于预览区下方；悬停可以查看工具名称。标题右边 `!` 显示完整校验诊断，`?` 显示当前编译器实际的步骤能力表。发布前进行完整编译检查；保存草稿不会改变目录或 FTB 任务。

列表底部 `E` 在文档和片段属性之间切换；点击步骤进入步骤属性。文档属性中的 `items` 是当前实例物品 ID 数组。属性新增行左侧为键名，右侧为 JSON 值；已有字符串直接编辑，数字、数组和对象按 JSON 输入。属性换页前应用当前页内容。超过表单长度的已有值以只读 `[R]` 保留，不在保存时截断。

模型区拖动旋转，滚轮缩放，`C` 重置取景。正文、分页、属性页不会驱动自动镜头；新片段首次打开会重新建立取景，编辑后改变结构范围需要显式重置镜头。时间线由确定性的预览事件求值，不驱动真实世界。

## 三维选点和属性选择

先选中步骤，再使用预览区下方的 `+` 选择该步骤实际使用的坐标字段，不是顶部的新建按钮。选择方块坐标时点击可见方块，选择范围时依次点击两个角；右键拖动和滚轮仍用于观察，Esc 取消本次选择。完整选区一次提交为一个撤销记录，取消不会留下半个范围。

选点使用当前模型、方块选择形状、相机以及结构的移动和旋转，不使用屏幕二维矩形猜坐标。`blockPos` 和方块选区保存源方块格坐标；本工具写入的 `point`、`pos`、`pivot`、`lookAt` 保存已变换后的绝对场景坐标，两者不能混用。文字、操作提示和菜单图片的绝对 `point` 同时标记 `pointSpace: "scene"`，不会因为这个坐标恰好落入另一个源方块而再次变换；旧稿未声明该标记时保留原有绑定语义。文字或图片改选绝对锚点时会清除竞争的旧方块绑定；需要跟随结构时应选择方块选区。链接结构的移动不再提供无效的选区字段；玩家已有显式朝向时也不会提供相冲突的 `lookAt`。

切换文档、片段、步骤，或稿件已经变化时，未完成的选点自动取消，不写到另一个对象。图形目标编辑会替换旧定位：从固定位置字幕重新选目标时清除 `independentY`，改选跟随方块时也清除旧绝对 `point`，不会出现界面已经选中但编译仍沿用旧定位的情况。未经图形编辑的旧稿仍保持原有定位优先级。当前步骤缺少必填坐标而不能编译时，选点可以仅在临时预览中跳过该步骤；原草稿、磁盘内容和发布校验不受影响。场景没有可见方块时需要先建立或导入结构，不能凭空命中一个方块。

受支持的方块、物品、声音、实体适配器和粒子字段提供可搜索选择列表，内容来自当前实例注册表或明确的本地适配器；未注册的高版本 ID 不会自动替换。NBT 入口先校验有界的复合标签，再审阅后应用；仍可保留不可发布的草稿，不执行标签中的代码或真实实体回调。

多行说明、审阅、导入、素材提示和标签描述统一按当前字体测量换行，已换行正文不再二次裁剪。Unicode 码点、中文和格式状态保留；更改字体设置后重新进入界面会重新测量文字，不因文字长度重新缩放模型。320×240 下模型和说明使用分离区域；标题、时间轴会按字体高度调整。原生按钮的大字体字形、复杂透明交错仍须按候选实绘记录验收，布局单元测试不是完整画面认证。

在正式播放器使用 `Ctrl+E`，把当前场景复制到新作者稿；原 Java 教学、原场景 ID 和 FTB 引用保持只读。可等价转换的动作保留时间和关键帧，无法表达的原事件带原因保留为不可发布草稿，不会悄悄删除。

`0.3.0-alpha.3` 起，复制场景中的完整方块实体快照使用 `modify_block_entity_nbt` 的 `nbtMode: "replace"`，确保原演示已删除的字段不会残留。手写文档未指定 `nbtMode` 时仍采用原有合并行为，也可明确使用 `"merge"`。`replace` 仅适用于带显式 `nbt` 的该步骤；旧版候选不支持此扩展，不能把新稿的发布结果当作旧版兼容证明。

## 作者工作区

每个实例的作者数据位于 `config/ponder_legacy/authoring`，不会写入旧 `scripts/ponder`。

| 路径 | 内容 |
| --- | --- |
| `drafts` | 作者草稿 |
| `published` | 已校验发布的文档 |
| `history` | 每文档最近 20 份自动历史 |
| `assets/structures` | 明确 ID 的结构 NBT |
| `assets/textures` | 素材包激活后的图片数据 |
| `inbox` | 待审阅的本地素材 ZIP |
| `imports` | 已确认导入的独立暂存包 |
| `exports` | 素材 ZIP、离线提示词、文本导出 |

保存使用内容哈希检查磁盘冲突和同目录原子发布。冲突时不覆盖他人的磁盘版本；未保存文稿保留在当前编辑会话，可以用文档属性的新 ID 另存。导入默认使用新的 `local:import_*` ID，先审阅字段差异再创建草稿；不会直接发布或替换原教学。

本地发布目录最多 64 个文档、JSON 合计 16 MiB、场景与物品绑定合计 256 条。重载只注册受限元数据，不在进入世界时编译全部作者场景或反复解压结构。资源和运行语义在发布及按需打开时严格验证。

编译前会计算实际展开量，不只检查 JSON 字符数。单份方块实体或物品 NBT 上限为 64 KiB UTF-8，文档展开 NBT 合计上限为 16 MiB；结构解码共用 64 MiB／一百万方块预算，世界和描边目标展开也有累计上限。单片段最多生成 256 个预览演员，普通演员动作不重复计数。超限保留草稿并报告原因，不先生成超大时间线再失败。

## Alpha4 时间线

编辑器步骤类型选择会为新镜头、声音、NBT 和粒子步骤补充缺失的默认字段，不覆盖已有字段或删除未知草稿数据。能力表中的 `CONVERTED` 表示明确的 1.12 转换，不表示与高版本任意参数完全等价。

| 步骤 | 行为及边界 |
| --- | --- |
| `zoom_scene` | `point` 为中心，`scale` 为默认视图的倍率，先平移后缩放；缺省目标回到默认视图。默认等待 `duration` 刻，清除步骤前的文字和描边，不清除同刻随后创建的提示。 |
| `rotate_camera_y` | `degrees` 为水平增量，`degreesX` 为可选俯仰增量；`duration` 是等待而非旋转动画长度。零等待默认瞬时，非零使用本地固定 18 刻动画。省略俯仰角不会中断此前俯仰动作。 |
| `encapsulate_bounds` | `bounds` 为从原点起的三个包含端点，各为 1 至 256；只扩展预计算取景范围，不向世界放置空气。 |
| `play_sound` | `sound` 必须是当前注册的 1.12 声音，`source` 为声音类别；只在屏幕预览正常向前播放时触发。回退、跳步、编译和世界投影均静音，关闭仅停止本预览的声音。 |
| `modify_entities_nbt` | 仅修改本片段的玩家、鹦鹉、矿车适配器，可用选区、`linkId` 或 `fullScene` 选择；支持显式视觉字段及有界位移，不调用真实实体的 NBT 加载。 |
| `modify_item_entities_nbt` | 修改隔离物品的 NBT 深拷贝，支持普通自定义物品标签及显式实体包装；拒绝身份、生命周期与未经适配的危险渲染载荷。 |
| `next_scene` | 与上游一致的边界标记，不等待、不自动切换；单独的演示页仍由 `scenes[]` 定义。 |
| `spawn_particles` | 支持 `point`、`box`、`sphere` 及三维 `spread`、`motion`；使用可重播的代表性彩色标记，不是原生粒子的完整模型。每发射器最多显示 12 个样本，每片段最多 256 发射器、65536 次声明发射量。 |

实体和物品移动是有限时间线位移，不模拟拾取、重力、碰撞或 AI。`Pos`、`Rotation`、`Motion` 与明确的外观字段由适配器处理；重叠的未完成变换、任意第三方实体、UUID/Owner 等身份载荷仍拒绝。物品普通自定义标签保留，`SkullOwner`、`BlockEntityTag`、`ForgeCaps` 需要专用适配器。合并后的完整快照仍检查 64 KiB，独立物品副本与序列化副本均计入文档展开预算。

`create_entity` 的玩家、鹦鹉、矿车可声明六方向或 `simultaneous` 入场，`entranceDuration` 默认为 20；从目标反方向半格滑入，零时长直接到位，不自动等待、不播放行走。入场与非零运动、NBT `Pos`／`Motion` 或行走动画目前需要拆成独立步骤。物品创建没有虚构自动入场，可通过明确的演员移动步骤完成。非玩家朝向使用 `yaw`／`pitch`；玩家 `lookAt` 不与另一组显式朝向混用。

复制已编译场景时，镜头使用明确的本地 `waitForCompletion: false`、`instant` 和旧版 `legacyAdditive` 标记保留非阻塞时序；普通手写上游稿不需要这些字段。受限 PonderJS 不能表达的新字段会明确拒绝导出，不会省略后伪称无损。

可声明式的原生纹理、GUI 子高亮及说明、静态三维线框、静态关注点，以及已知原版合成／熔炉／物流截图，可复制为 `native_overlay` 或 `native_point_of_interest`。只读取已知静态描述，不调用未知 provider 或 GUI 回调。复制的配方图是历史展示快照，不是当前注册配方匹配的证明，也不提供交互合成；正式教学和隔离练习仍查询实际配方。显示／隐藏通过本地 `fadeDuration`、`directionless` 保留原淡入时序，完整设置方块通过 `clearBlockEntityNbt` 保留同方块旧 NBT 的清除语义。未知动态提供器仍保留为不可发布草稿。

## 物品 NBT 入口

文档级 `nbtFilter` 为 SNBT 复合标签字符串；`itemNbtFilters` 按 `items` 的索引覆盖。显式 `null` 或空白表示该条目不筛选，只有缺失索引才继承全局过滤。复合标签按子集匹配，列表必须完整且顺序一致，数值类型保持 NBT 原类型；非法 SNBT 阻止发布，不按无过滤处理。

同物品可注册多份互不覆盖的作者文档，入口携带实际物品的副本进行匹配。FTB 自动物品入口合并所有对应任务物品和图标匹配到的演示；明确场景 ID 或旧序号入口继续按手动选择打开，不受此筛选影响。已有 MMCE 组件匹配规则没有改成新的列表匹配规则。

1.20 `components` 数据不能直接塞进 1.12 标签冒充兼容；必须先转换。序列化物品的 Count/count 不用于身份筛选，书籍标题采用明确的 1.12 兼容路径，其他标签仍执行完整条件。

## 蓝图和素材包

本轮工具和两个投影仪可从创造模式工具页取得，尚未提供生存合成配方。持思索蓝图左键选择起点，右键选择终点并捕获；仅允许读取全部已经加载的区块，尺寸每轴最多 64 格。

默认捕获只保留方块状态、方块实体注册 ID 和重定位坐标，不读取完整容器库存、身份或未知扩展载荷。完整 Tile NBT 只通过显式 API 策略开放，不是默认捕获行为。蓝图只读场景，左右键选择不会拆除或交互所选方块。

素材面板可以选择结构绑定到新稿，导出包含明确引用结构的素材包。ZIP 导入先校验路径、预算、内容和冲突，再明确确认暂存与激活；教学文档仍需单独审阅和发布。结构或文件冲突会拒绝覆盖，不会自动把高版本对象替换成空气或石头。

素材包和导入草稿的 `SCHEMA_ONLY` 审阅使用当前编译器的实际能力表，只说明格式及步骤类型是否可识别；不会在审阅时运行步骤或提前激活资源。PNG、NBT 和文件安全校验仍执行，缺失引用仍提示。确认导入不等于可以发布，发布仍须完整校验参数、当前注册表和已安装资源。

`show_extra_structure` 支持 90 度倍数的坐标及方块状态旋转，再将实际非空选区的最小坐标对齐 `blockPos`；`replaceAir=true` 则按完整声明尺寸放置，包括缺失的空气格。Tile NBT 使用独立副本并重写坐标，不支持任意角度的资产旋转。

Alpha5 为链接结构增加明确的区块归属时间线。重复使用同一链接会追加选区；方向或同时入场具有独立的临时组，完成后才合并。临时组继承目标当前的平移，最终合并后继承目标完整变换，不擅自反向重算来消除上游本身的合并姿态变化。`show_section_and_merge` 缺省从下方入场；原有 `show_structure` 的缺省行为保留。`smartDisplay` 区分已显示与隐藏格，不把镜头变化当作选区变化。

结构叠加到已移动或旋转的旧格时，旧归属明确释放，新方块使用新归属，旧临时组不会在后续刻重新把它拉回。隐藏、文字锚点、描边和选点共用这一变换求值。归属事件、嵌套合并和隐式成员展开都有预算，超限在编译时报告；不是任意深度或无限重复的高版本场景都能直接执行。复制场景以受限 `native_section` 记录保留这一历史，旧稿没有归属元数据时仍走旧的变换语义。

素材交换中的“图片素材”打开缩略图列表。把 PNG 放入作者工作区 `inbox`，选择“导入 PNG”，审阅后指定新的本地图片 ID；不会覆盖已有素材。选择图片和绑定片段后，追加原生 `show_image` 步骤。`image` 为本地 ID，`duration` 为演示时长，三维 `point` 或 `blockPos` 可把图片关联到具体目标；没有目标时显示在预览边缘。

单张 PNG 编码上限 8 MiB、边长不超过 2048、解码 RGBA 不超过 16 MiB；单文档最多 32 张不同图片，编码合计 32 MiB、解码合计 64 MiB。素材包以显式 `imageAssets` 和 `imageMappings` 记录来源与本地 ID，不能把高版本资源名当作已存在的 1.12 纹理。图片解码与上传按可见页面惰性进行，关闭预览释放已使用的纹理。

受限 PonderJS 只支持白名单字面量语法；不支持的语法或字段明确报错，不执行脚本。Java 输出是可审阅的 `AuthoringCompiler` 桥接源码文本，不会自动编译、运行或写入脚本执行目录。

离线提示词包含当前注册表、当前稿件、明确引用的结构和实际步骤能力。导出不发起网络请求、不扫描凭据；外部生成结果通过剪贴板 JSON 导入，先校验和查看差异，再保存为新稿。

## 隔离菜单

编辑器预览下方 `T` 或正式播放器 `Ctrl+J` 打开隔离菜单。作者文档中存在界面时间线时可选择对应定义；没有时提供工作台、熔炉、箱子、漏斗四种原版小示例。

### 原版界面捕获

编辑器预览区下方的 `[]` 开始一次有时限的捕获并回到世界，不是顶部的 JSON 导出按钮。然后由玩家正常打开工作台、熔炉、27 格箱子、54 格大箱子或漏斗，使用其界面上的捕获按钮。捕获按钮不点击容器槽位；接下来仍由玩家正常关闭原容器，再进入审阅。工作区不会替玩家放置、打开、关闭或操作真实容器。

关闭动画可以在服务器窗口关闭后短暂保留原界面。已经捕获的请求只对同一界面、同一世界和玩家等待最多 40 个客户端刻；必须等原界面真正消失、玩家容器恢复后才进入审阅。新的界面、容器重新打开或超时都会取消，不强制结束动画，也不绕过其他模组的关闭取消。

捕获只接受明确的原版界面、容器及槽位结构，模组菜单不会通过一个相似的界面名称冒充已适配。只记录容器物品的 ID、数量、损伤值和受支持的熔炉进度数据，不复制玩家背包 36 格、物品 NBT、身份或未知扩展。必须查看审阅摘要后才能确认；可分页查看全部槽位和数据，取消、超时、换世界或对象变更均不追加旧快照。

当前整合包的 FastWorkbench `1.7.4` 有单独的只读适配：验证已加载 JAR 的明确指纹、精确界面与容器类、原版 3×3 合成库存和完整 46 槽位身份后，才读取 10 个菜单槽。四个适配类的 CodeSource 和类资源必须指向同一本地 JAR；支持 Cleanroom 使用的标准 `jar:file:` 类资源来源，非空条目必须精确匹配该类，拒绝远程来源、其他条目或未知协议。来源记录区分 `fastbench:workbench` 与本地工作台演示适配器，不冒称原版界面；其他版本、修改过的 JAR 或未知子类仍拒绝。不会构造 FastWorkbench 容器、调用其合成/取出方法或导出玩家库存。

HammerLib `12.2.58` 的 `GuiFurnaceSmooth` 也有独立只读来源适配：只允许固定指纹的已加载 `hammercore` JAR、直接继承原版 `GuiFurnace` 的精确界面类和精确原版 `ContainerFurnace`。CodeSource 与类资源必须来自同一本地 JAR，且界面的容器必须就是捕获的已打开容器。仍逐一验证原版 3 个熔炉槽、36 个玩家槽身份和库存类型，只复制菜单的 ID/数量/变种及 4 个已同步进度值，不构造或调用 HammerLib 界面。草稿记录真实来源 `hammercore:furnace_smooth`，隔离演示适配器仍为 `minecraft:furnace`；旧的无界面参数捕获接口不伪造这个来源。酿造台、未知版本、子类、库存和槽位替换仍拒绝。

确认只向原编辑会话追加一个可撤销的 `show_interface` 草稿步骤，不自动保存或发布。大箱子的 `minecraft:generic_9x6` 是本项目明确的 1.12 本地适配器名，不表示 1.12 存在高版本菜单类型注册表。54 格菜单使用自身尺寸与独立槽位命中，不套用 27 格箱子的固定高度。

`show_interface` 同时创建播放器和嵌入式编辑器里的前景菜单快照，槽位及操作按当前场景时间求值。说明、菜单和图片在三维预览之后绘制，分页与滚轮优先处理，不同时拖动或缩放模型。不同场景实例各自持有快照，切换草稿或投影编译不会串用同名场景的数据。二维 `point` 只保留为来源元数据，不解释成三维方块目标；三维 `point` 或 `blockPos` 才建立目标绑定。

观看模式只回放；尝试和练习使用独立槽位、虚拟物料和游标。工作台和熔炉查询当前实例的注册配方，没有有效产物时明确显示，不虚构配方。漏斗每 8 个演示刻转移一个物品，熔炉默认按 200 个演示刻计算一次熔炼。暂停、回退、重置从同一定义重建状态。

原版熔炉默认周期为 200 刻；捕获或作者数据明确指定正数 `cookTotal` 时，快照、练习进度条和虚拟完成时机共用该周期。缺省或 0 保留原始数据并按 200 刻解释，不改写数据目标条件；时间线改变周期后仍可确定性回退和重播。这是演示数据，不会更改真实熔炉的工作速度。

`set_interface_data` 的上游 `id/from/to` 写法按演示刻插值。`id` 为 0 至 3，依次对应 `burnTime`、`fuelTime`、`cookTime`、`cookTotal`；本地也可明确使用这些 `key` 或 `locked`。`to` 优先于兼容的 `value`，未写 `from` 时从目标值开始，不读取真实容器。`duration` 缺省为 1，0 按 1 刻处理；首个样本已推进一刻，例如 4 刻从 0 到 100 依次为 25、50、75、100。数值必须是受限整数，键与 ID 冲突、未知数据字段或超出总时间预算会阻止发布，不静默忽略。

旧的本地 `key/value` 写法仍瞬时赋值；含显式 `id`、`from` 或 `to` 时采用插值。相同键的多个插值按声明顺序处理，后创建且仍在运行的指令优先；它结束后，尚未结束的旧指令可以继续。瞬时赋值覆盖当前刻，下一刻仍在运行的插值继续。观看与尝试先计算虚拟机制再应用脚本，练习模式不替玩家执行脚本动作；暂停、回退和重置会按同一规则重建。这里只改变隔离的演示数值，单独改变进度并不代表已经消耗材料或生成产物。

Shift 快速移动按各原版容器区分：工作台的玩家主背包与快捷栏互转，不自动填入合成网格；熔炉先判断有效熔炼输入，再判断燃料，其余物品在玩家区互转；箱子和漏斗取出时从玩家区末端开始合并。合并先补已有同类堆叠，再使用空格，保留物品标签、堆叠上限和当前虚拟游标。燃料槽中的空桶最多一只。

工作台快速取出使用有界重复合成，一次最多 64 次；必须容得下完整产物和配方余物才提交这一批次。没有虚拟空间时保留原材料，已经完成的批次不会被回滚。这里不调用真实容器的取出、成就或掉落回调，也不会把虚拟溢出物丢进真实世界，因此不是任意模组工作台回调的无条件复刻。

未知菜单只读，任意第三方 GUI 回调、流体 ghost 槽和不支持的动作拒绝发布。练习不访问真实玩家容器、不发送点击包、不改变世界、FTB 进度或奖励。玩家捕获前主动打开或关闭原版容器属于正常游戏交互，不能与之后隔离练习的零真实交互混为一谈。

高版本菜单的非空 `interface.extraData` 属于原始打开字节，不解码或重放；含有该数据的文档只能保留草稿，需改成受支持的声明式槽位描述。数据插值覆盖自身的完整显示周期，但不阻塞后续步骤；需要后续讲解等待时应显式添加 `idle`。瞬时操作恰在菜单显示时长终点时，仍需延长 `duration` 才能查看结果。

## 世界投影 Alpha

微缩和实景投影仪默认暂停。右键打开配置，选择组件及其稳定场景 ID，再设置速度、朝向、比例、循环和红石触发。配置只在单人整合服务端的调度线程提交，重新核验玩家、维度、距离、区块和目标方块实体。

世界渲染只处理 32 格内最近四台，每台最多 4096 个方块、64 个演员，并限制事件预算。超限显示原因，改用屏幕演示，不截掉一部分结构假装成功。几何与人物复用现有预览；世界路径不清除真实世界深度，轮廓不会透过真实墙体显示。

绑定保存稳定场景 ID 与注册条目位置，重载后会核验实际 ID；不匹配时要求重新绑定，不切换到另一个同物品教学。新绑定、手动重启和触发模式切换会清理旧上升沿状态。

世界投影复用确定性粒子标记及前景说明。粒子不进入真实世界粒子系统；粒子与玻璃、水仍采用分开的透明绘制顺序，复杂交错不能宣称像素级正确。四台投影可以同时显示几何，但仅视线中心附近的一台拥有前景说明。右键配置中的“阅读”打开透明、不暂停的阅读层，说明可以分页，Esc 返回配置；未应用的表单不会改变当前投影。离屏、卸载、切换场景或窗口缩放后不会复用旧标签和点击区域。

坐标和结构提示仅接受明确的 1.12 映射，不会自动打开演示。`triggerMode` 配合 `legacyTrigger.version=1`、维度、场景和适配器配置；坐标适配器为 `coordinate_aabb`，结构适配器为 `block_pattern`。结构匹配最多 128 个明确方块状态，只读已加载区块，不触发区块生成。每 20 个可操作客户端刻最多检查 8 条规则、读取 512 个方块。

匹配提示以操作栏文字出现，P 打开该提示对应的稳定场景。当前已读状态限定在世界会话内：`first_time` 与 `until_read` 成功打开后释放快捷键，P 恢复目录行为；退出世界再进入会重新建立会话。`always` 允许重复打开。未提供受支持映射的上游触发元数据保留草稿并阻止发布。普通放置、红石、保存重进及完整画面矩阵仍以本候选原生验收记录为准，不能以单元测试代替。
